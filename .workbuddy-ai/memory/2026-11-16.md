# 2026-11-16 — the §10.5 shot-head test, and three defects it exposed

## 1. BPTT was silently corrupt for every shipped brain

`SituationalBrain.backward` computed the situation width as the MODULE constant
`ROLE_D + STATE_D + MEMORY_D + PLAN_D` (24+19+8+6 = 57). Every shipped brain has a
NINE-wide role block (`w_q` is `(47, 32)`), so the real width is 47 and
`dctx = du[57:]` sliced 22 of 32 context gradients off the end of a 79-long vector.
The GRU gate gradients were written from a truncated vector. No exception.

Consequence: **any supervised/BPTT training of the shipped situational brains was
writing garbage into the GRU.** The module-default 19-wide case was the only one that
ever worked, and no shipped brain uses it.

Fixed: `smp = int(self.w_q.shape[0])`, plus the `d_role`/`d_memory`/`d_plan` slices
derived from `smp`. `tests/test_bptt_gradients.py` checks analytic vs finite-difference
gradients at BOTH widths (47 and 57) and at the input blocks; reverting the fix fails
3 of its 5 tests at exactly the shipped width, so the test has teeth.

## 2. The evolution path cannot produce a SituationalBrain (NOT fixed)

`brain_self_trainer.evolve()` -> `evolve_all_parallel.py` with no `--role-features` and
no `--tactics-context` -> `evolve_brains.py` with `input_size = 24` -> `FootballBrain`
(flat MLP). `promote()` then copies `challenger/<POS>.json` over `brains/<POS>.json`.
The shipped brains are `SituationalBrain` (arch 3, attention + GRU, 15,150 params).

So the trainer's GA is a cross-architecture comparison, and a gate win would replace a
15k-param situational brain with a flat MLP. `brains_trainer/trainer_log.jsonl` shows one
promotion (2026-09-12, fitness_delta +0.1096) that did exactly that; the v5 set was
restored later.

**Do not run `brain_self_trainer.py` evolve against `brains/` until this is addressed.**
The audit script passing ("safe to evolve") only says the reward TABLE is sound; it says
nothing about whether the evolution harness produces the right class of brain.

Also: `brains/ST.json` and `brains/CF.json` are byte-identical (same md5) — ST and CF
share one policy.

## 3. §10.5 answered: the representation is fine, the head is inverted

`tools/diag/_shothead_probe.py`, shipped ST brain, 400-2000 synthetic scoring states from
`brain_evolution.random_game_state_scoring`, labels from `attacking_matrix.shot_score`
(verified sane: 2.97 at 1 m, 0.30 at 15 m, 0.02 at 45 m, symmetric both directions).

- Linear probe on the FROZEN 32-d hidden state: **AUC 0.95**.
- The shipped output layer, same hidden state: **AUC 0.28, spearman -0.51** — inverted.
- §10.3 as written (retrain the shared head): fixes the ordering (AUC 0.83) and destroys
  the policy (21 % of choices survive, argmax -> SWITCH 88 %). A KL anchor keeps the
  policy (92 %) and gives the ordering back to chance (AUC 0.45). Monotone frontier; a
  single scalar cannot buy both.
- Dedicated 33-param read-out on the frozen hidden state, added to the SHOOT logit ONLY:
  AUC 0.945, spearman +0.75, 92 % of untouched states left alone, SHOOT taken on 78 % of
  shootable states (was 0 %).

## The bias had to be clamped — it was a veto, not a prior

At `beta = 6` the RAW bias on the shipped ST brain ran **−103.7 to +15.4** over 400 real
hidden states. −104 means `p_SHOOT = 0.0` exactly: the brain could never shoot there, which
contradicts §10.3's own "it may decline a shootable ball" and is unbounded on any
out-of-distribution hidden state. `BIAS_CLAMP = 6.0` (±`e^6` ≈ 400:1 odds) now lives inside
`ShotHead.bias()`, so the fitted trial numbers describe the function that actually ships.
Unclamped the same head read AUC 0.855 / 59 % / 82 %; clamped it reads 0.822 / 56 % / 83 %.
The unclamped numbers were better and would have shipped a hard switch.

## THE FORK — why the shot gate returned an identical match

The re-gate came back bit-identical ON vs OFF (3-5, xG 0.91, shots 3, fit 0.6093 to four
decimals). On the synthetic corpus the same head flips 134/1200 states, so "identical"
could not mean "no effect". It meant "not applied".

**Root cause.** `brain_integration._maybe_situational` was not a router. It contained a
**complete second copy** of the situational pipeline (129 lines: FOV gate, tokens, four
blocks, recurrent forward, plan, consequence, temperature, sampling). `situational_decision`
held the same pipeline, documented and unit-tested, and was imported by **nothing but its
own tests**. `git show HEAD:brain_integration.py | grep -c SituationalDecisionBrain` → **0**.

So the shot read-out was wired, tested and gated against a program that never ran. The
temperament "reconnection" was dead for the same reason. The two copies had already drifted
(the fork re-padded the role block by hand; `forward_logits` already does that itself).

**Fix.** `_maybe_situational` is now a type check + import + call. Behaviour proven neutral:
the OFF arm reproduced the known fingerprint **exactly** (3-5, goals 3, xg 0.91, shots 3,
poss 51.2, fit 0.6093) after deleting the copy.

**Near-miss caught in time.** Delegating would have switched temperament ON in every season
run, because `auto_run_match` registers a mind per player while `match_probe` registers none
— so gated experiments would show nothing and real seasons would change. Added
`PLOFA_TEMPER` (default OFF) and `tests/test_temperament_live.py::test_the_switch_is_off_by_default`.

**Tests.** `tests/test_situational_routing.py` (5): delegates, refuses a FootballBrain,
degrades to None on failure, source-length guard (the router must stay a router), and
"the module is referenced at all". Verified to have teeth by running the spy assertion
against the old file: it served a decision while never entering the shared pipeline.

**New diag.** `tools/diag/_route_probe.py` — answers in seconds what a 4-min match cannot:
routing (decide entered), seam (head reached / changed logits), effect (argmax flips),
and **leakage** (the same measurement with the consequence critic pinned to identity).

**Leakage result: zero.** 109 bare vs 109 live flips — the critic neither adds nor removes
read-out flips, so the "a SHOOT-only read-out cannot reorder the other nine intents"
argument survives. On ST (200 states, 50 % final third): SHOOT chosen 75 → 36, of which

## The gate, with the wire live: REFUSED at all eleven positions

With routing fixed, the ON arm finally differed — and it was **negative**:
OFF `3-5, goals 3, xg 0.91, shots 3, fit 0.6093` → ON `2-2, goals 2, xg 0.92, shots 0,
fit 0.5591`. The head silenced the striker completely (both ON goals were own goals).

**Why the metric authorised it.** `MIN_CLEAN` measures collateral over states that are
neither shootable nor already shooting — so it **excludes every state where the brain was
shooting**, and the head was never charged for silencing a shot. `MIN_SHOT_RATE` counts only
geometry-shootable states. Between them, overruling the brain was free. Measured on the
shipped ST head: 66 % of states pinned at the ±6 clamp wall, |bias| > |gap| on 76.5 %.

**Added:** `MAX_OVERRULE = 0.15`, `MAX_SILENCED = 0.10`, both over EVERY held-out state.

**Refit → all 11 REFUSED.** ST AUC by beta: 0.356 (β0.5) / 0.634 / 0.814 / 0.852 (β2.0).
`silenced` ≈ 27 % at *every* beta. So the head only beats chance by becoming large enough to
overrule, and it silences shots even when tiny because the brain's shot decisions are
near-ties. **A sidecar cannot be a safe prior here**: safe ⇒ AUC < chance; useful ⇒
replacement ⇒ wrong on real states. The information is in the hidden state (probe 0.95); the
output layer reads it backwards; a 33-param patch cannot fix a sign error without taking over.

**State:** `brains/shot_heads/` holds only `_report.json`. Seam inert behind
`PLOFA_SHOT_HEAD`. Fitter now DELETES a stale artifact for a refused position (the beta-4.0
head survived one refit that way). Docs: RETRAIN_PLAN §10.5.3.

P1.3 is parked. The foresight plan is the live thread.

## THE ROOT CAUSE OF INDIFFERENCE: the scoreline was never in the training data

Following §4.1 (policy ignores score_diff/minute) upstream, three defects, all measured:

**(a) `surrogate_collect._snapshot_decide` decoded `decide`'s positional args ONE SLOT RIGHT.**
`event_chain.py:2098` passes NINE positionals after the player (`minute` is a keyword).
The wrapper read args[7]/[8]/[9] instead of [6]/[7]/[8]:
  believed under_pressure -> got attacks_right
  believed attacks_right  -> got game_state (enum ⇒ ALWAYS truthy)
  believed game_state     -> got nothing (args[9] absent) ⇒ None
Proven with a stub against the engine's exact call shape.
⇒ `_score_diff_of(None)` = 0 always, and `attacks_right` always True.
Measured on `brains_trainer/corpus.raw.json`: **score_diff is exactly 0.0 in 100 % of the
15,426 rows** (minute DOES vary 0.011→1.000 — it arrives as a kwarg, so the fallback
accidentally landed right, which is why the bug was invisible).
⇒ every decision, **the away team's included**, was perceived as attacking RIGHT. Half the
corpus is geometrically mirrored.

**(b) `_score_diff_of` mapped 4 of 7 engine states wrongly.** HOME/ AWAY_CRUISE → 0 (a 2-goal
lead read as level — LIVE); HOME_CHASE → +1, AWAY_CHASE → −1 (sign inverted — latent, the
engine's `game_state` property never emits CHASE). Rewritten as a table; 14 tests in
`tests/test_scoreline_reaches_the_brain.py`.

**(c) The table has no urgency dimension anyway.** `FitnessSurrogate.bucket` =
`P·FT·OH·S·C·G | A·M·D` — no scoreline, no clock. So even varied data would be averaged back
to indifference within each cell.

**Fixes shipped:** `_decode_situational_args()` extracted as a pure, testable function (same
principle as moving the temper switch to the call site); corrected score table; docs
`FORESIGHT_PLAN` §4.2.

**Implication to keep in mind:** the shipped brains were distilled from a corpus with half
the decisions mirrored and no scoreline. That plausibly explains the anti-correlated
`p_SHOOT` too. A RECOLLECTION is the precondition for step 2 and for any credible retrain —
not optional housekeeping.

## PRE-FLIGHT BEFORE THE 80-MINUTE RUN — three more bugs, found in minutes

User's objection was correct: the recollection was NOT a surebet. Built
`tools/diag/_mirror_symmetry_probe.py` (attacking left = attacking right rotated 180° on a
**105 x 68** pitch) and it found three genuine defects that an 80-min run would have baked in:

1. **`brain_sensors._goal_geometry` — branch-cut bug.** `abs(a_top - a_bottom)` without
   wrapping. For the away team `dx < 0`, both post angles sit near ±π, so the difference came
   out ~5.92 rad instead of 0.36 and clamped to 1.0. **An away striker 20 m out DEAD CENTRAL
   read the goal mouth as 1.000 (penalty-spot wide) instead of 0.563.** Live in every match.
   Fix: wrap the difference into (-π, π] — a mouth is an angle between two rays.
2. **`situation_tokens` — `dy` was not direction-relative.** `dx` was flipped for the away
   team, `dy` was not, so the signed lateral feature used absolute y and the two teams saw
   OPPOSITE conventions for the same geometry.
3. **`situation_tokens` — SPACE measured the corner flag.** `collect()` returns TUPLES
   `(d, player, px, py)`; `others` was passed straight to `_nearest_opponent_gap`, which calls
   `_pos_of` → a tuple has no `.name` → returns `(0.0, 0.0)`. So "gap to the nearest marker"
   was **the distance from that player to the pitch ORIGIN**, clamped. A 2 m marker read as
   22 m of space. Invisible for months because the origin is a fixed point: on the home half
   it correlates with attacking progress, and the corpus was 100 % attacking-right.

After the fixes: sensors symmetric to 1e-9 except ball_x/ball_y (absolute, must move);
role block 1.6e-15; token set 1.1e-15. `tests/test_mirror_symmetry.py` (22 tests).

**Also wired: stakes now reaches the reward.** `DecisionRecord.score_diff`, `_stakes_mult()`,
`_event_success(stakes_mult=)`, both call sites, `--no-stakes`, and `stakes_applied` in the
surrogate metadata so a corpus can never be ambiguous about what built it. Measured:
level 88' 1.47, 1-down 88' 1.56, 2-up 88' 0.67, OFF exactly 1.0.

## Gate 8 — the scoreline was in the wrong frame for half the players

`_score_diff_of` answers "how far ahead is HOME". `brain_sensors` stored it at slot 18 with
no team flip, so an away player 2-0 UP read **−2**. Measured on the pre-fix 3-match pilot:
range `+0.000 .. +0.400`, and **0.0 % of 1,250 steps where either team was behind** — even
in a match that finished 3-0.

Fix: `brain_integration._player_score_diff(game_state, attacks_right)`. `attacks_right` IS
team identity in this engine (`set_squad`: `team_name == home_team`; `MatchState` never
swaps ends), so the frame is a sign flip in ONE place, used by both the live path
(`situational_decision.decide`) and the collector (sensors + record + stakes). It raises on a
non-bool rather than coercing — a truthy `GameState` enum is exactly the shape of the
off-by-one that made the shipped corpus 100 % attacking-right.

## The uniform multiplier was arithmetically incapable of working

`stakes()` scaled the whole return by one number. **k·a > k·b exactly when a > b** for any
k > 0 — so a uniform multiplier changes *confidence*, never *choice*. A corpus labelled that
way distils to the same indifferent policy at any size, and every cell keeps its argmax.
This is now a property test so nobody re-introduces the scalar expecting behaviour change.

Fix: `threat_reward.stakes_pair(score_diff, minute) -> (gain, loss)`. Win probability is
convex when behind and concave when ahead: chasing → gains up, losses down; protecting →
gains down, losses up. At 88': 2-down (1.23, 0.49), 1-up (0.77, 1.42). `stakes()` is kept
unchanged as the published scalar for reporting.

## Gate 6 — the partition was measured and REJECTED

Plan was to append `K{behind,level,ahead}T{early,mid,late}` to the bucket key. Measured first:

| table | rich samples | rich cells | per cell | cells with ONE sample |
|---|---|---|---|---|
| shipped `surrogate_refit.json` | 15,426 | 2,685 | 5.75 | 40.5 % |
| 3-match pilot | 1,658 | 746 | 2.22 | 59.9 % |

A 9-way split takes the shipped table to **0.64 samples/cell** — noise, and noise in a reward
table is worse than indifference because it is invisible (the player looks erratic, not
uninterested). Replaced with a **pooled additive shift**: one number per (position, band,
intent) = mean residual of that intent's samples against the **coarse parent cell**, shrunk
toward 0 with 5 pseudo-observations. The parent, not the rich cell, because a rich cell with
one observation has a residual of identically zero — the estimate would vanish exactly where
the situation is unusual. Verified: a known 0.80 band contrast is recovered to within 10 %.

Backward compatible: 2,000 comparisons on a pre-change table, 0 differences.

## Gate 7 — split into DESIGN and EFFECT

A 3-match pilot shrinks every shift to ~20 % of its measured value, so a flip-rate threshold
would fail the *design* for a reason that has nothing to do with the design. The tool now
reports both: **design** (are the shifts differentiated across intents, and are any decisions
close enough to a tie for them to matter) and **effect** (how many actually flip). Only design
is binding on a pilot.

## RESUME WAS BROKEN — fixed (found while checking chunking feasibility)

The user rejected the 27-match collection as too much CPU and asked whether it
could be split into small chunks. Checking that question found two silent
data-loss defects in `surrogate_collect.py`:

1. `save_situational_corpus` rebuilt the file from the CURRENT process's
   records only. A resumed chunk holds just its own matches, so it overwrote
   the earlier ones while stamping the file with the TOTAL match count — the
   next chunk then skipped the total and the early matches were gone, with
   nothing on disk to say so. Fixed by `prior_sequences=`: the sequences
   already on disk are read back verbatim (`load_situational_sequences`) and
   written out ahead of the new ones. Sequences are built per (team, player)
   and never merged across matches, so concatenation is the whole repair.
2. The CLI wrote the corpus a SECOND time after collection with no count and
   no prior, resetting `matches_completed` to 0 on every exit — so resume was
   dead at the CLI level and every run looked like a first run. Removed; the
   file on disk is authoritative and the exit now just reports it.
3. ε-exploration used ONE `random.Random` stream for the whole run, so match 7
   explored differently depending on how many matches preceded it — i.e. a
   chunked collection was a different experiment. Now seeded per match:
   `Random((seed + 977) * 100003 + m)`.

`tests/test_collector_resume.py` (new, 8 tests): prior survives, sequences
preserved byte-for-byte, count is the total, two chunks == one run, corrupt
file reads as empty, and a source-level guard that NO call site may write the
corpus without `matches_completed=` and `prior_sequences=`.

Result: 8 new tests pass; 129 related tests still pass.

### Chunking semantics (for the user)
`--matches N` is the TARGET TOTAL, not the increment. To go from 3 matches to
7, pass `--matches 7` against the same `--situational-out`. Each match writes
the corpus, so stopping costs at most the match in flight.
